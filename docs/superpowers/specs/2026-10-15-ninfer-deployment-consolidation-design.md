# NInfer 生产部署收束设计

**状态：已确认，待实施计划与执行授权**

## 目标

把 AI 主机的 NInfer 部署收束为一个可运行、可审计、可重建的最小闭包：生产模型与下载暂存分离，WebUI 使用专用固定 Python 环境，源码、部署定义、文档和最小验证脚本以本地仓库根目录为唯一版本化事实来源；历史测试、构建副产物、日志和重复资料在替代链验证后淘汰。

本设计不授权直接删除生产依赖。任何删除均以替代资产完成实际启动、健康检查和真实推理验证为前提。

## 已核实的现状（2026-10-15）

- 生产服务由用户级 `ninfer-webui.service` 托管；引擎与面板健康端点正常。
- 当前引擎直接运行 `~/llm-deploy/build-ninfer-sm86-clean/apps/ninfer-serve`，并加载 `~/llm-deploy/micromamba/envs/ninfer-build/` 的动态库。因此这两项在切换前是生产依赖。
- 当前模型直接从 `~/llm-deploy/quark-downloads/swift-qwen38-q4km.ninfer` 加载。该模型是生产必要资产，禁止在新路径验证前移动或删除。
- GPU4 当前没有 NInfer 测试实例；其历史测试目录可在可复建最小验证链建立后淘汰。
- AI 主机源码工作树包含未提交的 B06 per-lane KVMem 改动；它们必须先被导出、审阅并纳入受控版本历史，不能在远端收敛时丢失。
- 本地仓库根目录比 AI 主机工作树多出在线 cache-clear 的四个提交；远端没有本地未有的受跟踪文件。

## 终态

```text
~/llm-deploy/
├── src/
│   └── ninfer-fusion-kvmem/       # 受版本控制的源码检出；工作树干净
├── runtime/
│   ├── webui-venv/                # 专用、固定、可重建的 WebUI Python venv
│   └── build-current/             # 唯一生产构建目录（验证后再切换）
├── models/
│   └── swift-qwen38-q4km.ninfer   # 当前生产模型；不是下载缓存
├── webui/                         # 面板源码、非秘密运行配置、受控日志策略
└── staging/                       # 短生命周期下载暂存，可清空
```

`~/llm-deploy/models/` 是模型稳定位置。目录小写；模型不进入 Git，也不作为可清理副产物。

## 持久化边界

### 版本化事实来源：本地仓库根目录

以下内容必须进入受版本控制的部署定义，且不得依赖 AI 主机上散落的副本：

```text
.
├── src-tree/fusion-engine-src/    # 固定源码提交
├── deploy/
│   ├── webui/                     # 面板源码与无秘密配置模板
│   ├── systemd/                   # 服务单元模板
│   ├── env/                       # Python 依赖约束和 venv 重建定义
│   ├── scripts/                   # 构建、部署、模型校验、健康检查
│   └── tests/                     # 可重复运行的最小 smoke/契约测试
└── docs/
    ├── deployment.md              # 唯一部署与重建入口
    ├── operations.md              # 运维、维护窗口、升级与验证
    ├── model-artifacts.md         # 模型名称、哈希、许可/来源说明；无秘密
    └── testing.md                 # 临时隔离验证流程；无历史输出
```

`.ninfer` 文件、构建目录、二进制、venv、micromamba 安装目录、下载缓存、日志、指标快照、`__pycache__`、历史请求/响应和 `.env` 均不进入 Git。

### AI 主机持久运行闭包

生产保留：

- 当前模型 `~/llm-deploy/models/swift-qwen38-q4km.ninfer`；
- 一个经过验证的生产构建目录；
- 该构建运行所需的明确运行库/环境；
- 专用 WebUI venv；
- WebUI 源码、无秘密配置与启用的 systemd 单元。

`qdl.env` 是秘密文件：不读取值、不复制、不提交、不打印、不删除。只有模型来源与下载链已被独立重建后，才可单列请求删除授权。

## 实施顺序与安全门

### 1. 保护未版本化源码工作

1. 只读记录远端 B06 改动的文件清单和 diff。
2. 导出为可审阅补丁并复制到本地受控工作区；导出后校验补丁可应用。
3. 在本地分支上整理为测试覆盖的提交，并验证它与本地 online cache-clear 改动兼容。
4. 仅在该版本化结果被确认后，才允许远端源码工作树恢复干净状态。

### 2. 建立版本化部署定义

1. 将当前实际 WebUI 源码、无秘密配置与 systemd 语义迁入 `deploy/`。
2. 建立可固定依赖版本的 WebUI venv 定义；venv 本身不入库。
3. 建立构建、模型校验、端点健康检查与真实生成验证脚本。
4. 把散落且过时的操作文档压缩为唯一当前文档；历史论证和测试输出不继续保存为运维指南。
5. 瘦身 `AGENTS.md`：只保留生产安全、秘密处理、可重建性和冻结端点契约，删除易腐的运行时路径、GPU/端口分配、PID、回退文件名、历史性能结论与测试基线数量。

### 3. 模型与 Python 运行时迁移

1. 复制（不是移动）当前模型至 `~/llm-deploy/models/`。
2. 对源与副本计算强哈希并逐字节比对；记录目标模型的哈希，不记录下载 Cookie/URL。
3. 创建 `runtime/webui-venv/`，从版本化依赖定义安装 WebUI 所需包。
4. 生成 systemd 单元的候选版本，使其显式执行专用 venv Python，且引擎参数引用 `models/` 路径。
5. 在维护窗口启动该候选链，验证：服务状态、`/health`、面板状态、真实生成请求，以及一次受控重启后的恢复。
6. 仅在以上验证通过后，允许删除原模型副本和旧 Python 环境。

### 4. 构建目录规范化

不在模型/venv 迁移阶段搬动当前正在运行的二进制。当前 `build-ninfer-sm86-clean/` 是已知可运行构建，保持原位。

随后由版本化源码与构建定义创建 `runtime/build-current/`，在维护窗口切换并重复第 3 节的完整验证。成功后，旧构建目录和不再需要的 `micromamba` 运行环境才成为删除候选。若新构建仍需 `micromamba`，必须保留一个最小且明确受管理的环境，不得为了“瘦身”破坏重建能力。

### 5. 清理

每个删除批次都必须先生成清单，说明路径、大小、引用证据、替代物和验证证据。

在对应替代链验证后可清理：

- 历史隔离构建、构建日志、源码 `.bak*`；
- GPU4 测试资产、历史 A/B 数据、请求响应、旧测试脚本和日志；
- WebUI `.bak*`、`__pycache__` 和已轮转日志；
- 未使用的旧 venv、下载工具运行痕迹、驱动库副本；
- `quark-downloads/` 中除迁移并验证后的生产模型外的内容；整个目录只在模型迁移成功后删除或改建为 `staging/`；
- 本地外层目录的重复镜像、历史 archive、一次性补丁和已被正式文档吸收的历史材料；
- `models/` 内除当前生产模型外的文件，但须先逐文件核验引用、来源和哈希。

## 验收标准

完成后必须有以下可重复证据：

1. AI 主机上只有一个清晰的生产模型路径，且模型完整性哈希与版本化模型文档一致。
2. systemd 使用专用 WebUI venv，不依赖系统 Python 作为应用运行时。
3. 当前生产二进制与其运行库有清晰、可重建的来源；不保留未定义用途的历史构建目录。
4. 每次切换均通过服务状态、`/health`、面板状态、真实生成请求和受控重启恢复检查。
5. 远端源码工作树干净，所有需要保留的改动均已在本地 Git 历史或待审补丁中。
6. 仓库根目录是非秘密部署定义和文档的唯一版本化事实来源。
7. `qdl.env` 从未被读取、迁移或提交；若未来删除，另有显式授权与审计记录。
8. 未保留 GPU4 常驻测试环境、历史 A/B 结果或构建/下载/日志副产物。

## 非目标

- 本轮不删除当前模型、当前运行构建或其运行库。
- 本轮不读取或处理任何秘密的值。
- 本轮不将模型、编译物、环境目录或运行日志放入版本库。
- 本轮不把临时测试 GPU 固化为生产部署要求。
- 本轮不修改 KVMem/ActKV 功能；其融合分析将在部署收束完成后单独进行。
