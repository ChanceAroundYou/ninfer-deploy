# ninfer-deploy agent rules

## Production safety

- Treat production as read-only unless a requested, approved maintenance action says otherwise.
- Before a production change, identify the exact service, process, model, binary, and runtime-library dependencies.
- Never use broad process termination such as `pkill -f`; inspect the exact PID or service cgroup first.
- Do not delete a production binary, runtime library, or model until a replacement has been switched over and verified by health, WebUI status, a real generation request, and restart recovery.
- Keep build directories separate from source directories. A deployment must be reproducible from versioned source and documented non-secret definitions.

## Secrets and artifacts

- Never read, print, copy, or commit `.env` values, cookies, download URLs, tokens, or credentials.
- Keep models, build outputs, virtual environments, download staging, logs, caches, and generated bytecode out of Git.
- `qdl.env` is a protected secret. Do not migrate or delete it without a separate explicit authorization.

## Contracts

- Management API changes require matching tests and current documentation.
- Preserve the cache-clear contract: `POST /v1/admin/cache/clear` returns `202 {clear_id}`; status is fetched by `GET …/{id}`. Supported modes and scope semantics must remain documented and tested.
